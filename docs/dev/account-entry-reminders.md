# 账户记账确认提醒

每个真实账户（不限账户类型）在账户详情中提供「账户记账提醒」。默认关闭，一条配置固定归属账户及其账本，不跟随当前浏览账本。支持提醒名称、收入/支出、账户币种金额、分类、本地时刻、重复日期，以及「确认方式」中的确认/取消按钮文字；留空使用当前语言的默认「确定 / 取消」，自定义文字最多 12 个字符。

## 中国大陆工作日（含调休）

「重复日期」可选「自定义星期」或「中国大陆工作日（含调休）」。旧配置缺少 `repeatMode` 时保留自定义星期；切换模式保留原星期选择，工作日模式不与星期选择取交集。`matchesDate` 用于确认记账前校验，原生 `AccountReminderSchedule.matches` 以同一日历核对通知发送日期。

- 日历使用**设备本地日期和时刻**：周末补班优先为工作日，全部放假日期跳过，其余按周一至周五。只覆盖中国大陆全国统一安排，不含地方节日、单位排班和个人请假；没有新增 Android 权限，联网更新须另行主动开启。
- 内置兜底数据为 `lib/app/reminder/china_workday_calendar.dart`，当前内置 **2026 年**。依据[国办发明电〔2025〕7号政府转载](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)：放假共 33 天，周末补班为 1/4、2/14、2/28、5/9、9/20、10/10。Controller 将其与已经校验并落盘的下载年度合并，不能仅根据农历推算调休。
- 默认 `missingCalendarPolicy: pause`，缺失年份不安排提醒；用户可明确选择 `weekdays`，只在缺失年份按周一至周五降级（此时无法跳过假期或加入周末补班）。未知策略按暂停，未知重复模式停用。设置页展示覆盖年份、处理方式和当前缺失状态；启动、回前台及前台跨年时用根级轻提示说明暂停/降级，同状态在本次应用会话内去重。
- Flutter 投影把版本化 `workdayCalendar`（`version: 1`、`years`、`holidays`/`workdays`）和配置一起交给原生私有存储，月日编码为 `月 × 100 + 日`。重启、进程回收后由原生独立查表，不依赖 Flutter 常驻或网络请求。日历不写入账本备份，没有第二套生产调休表或新增依赖。
- 下一次排程按日历日向后查找最多 366 天，覆盖超过一周的春节长假；送达前与用户确认时再次核对日期规则，未知年度不会按普通工作周静默继续。每次日历快照同步都撤销旧闹钟并重排；若今天已不符合新规则，同时撤销今天旧的正式通知。

维护内置兜底时，在同一数据文件补充全年日期和官方来源，并更新逐日回归、覆盖年份相关断言及本文；**更新应用并打开一次**后同步内置数据。用户也可通过下述联网更新获取新年度，无须为每个年度更新应用。当前不提供个人例外日期编辑。

## 可选的联网日历更新

入口：**资产 → 对应账户 → 账户记账提醒 → 重复日期选择中国大陆工作日（含调休）→ 工作日日历**。工具页是全设备共用设置，开关即时保存；进入此页不会保存或丢弃上一页的账户草稿。默认关闭，单纯进入页面或手动调用 force 检查均不能绕过联网授权。

- 用户开启后立即检查；之后在应用启动、回前台和前台跨日尝试检查当前及下一年度。普通自动检查以 24 小时真实时长节流；**跨年和系统时间回拨时重新检查**，因此 12 月 31 日 23:59 检查过，也不阻止 1 月 1 日第一次打开时检查新年度。用户可点「立即检查」绕过节流。
- 检查完成时若当天提醒时刻已过，仍沿用不补发的既有语义，从下一个有效时刻继续安排。
- 数据来自 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)，依次访问 `https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/{year}.json` 与 `https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json`。这是第三方整理的国务院公告数据，**不是国务院官方在线接口**。请求只含公共年份路径，无账目、账户或设备标识；服务方可见 IP 等常规连接信息。隐私政策同步说明，未新增依赖或系统权限。
- 客户端仅 HTTPS，不跟随重定向，单次地址请求总超时 12 秒、连接超时 6 秒，分块累计超过 64 KiB 立即停止。年度须匹配请求，日期须严格有效、不重复；公告须为中国政府网 HTTPS 链接，七类全国节日均须有本年放假记录。兼容中秋/国庆合并名称及省略普通连休周末；这是结构/覆盖校验，不是对第三方公告真实性的独立认证。
- HTTP 404 或 `papers: []` + `days: []` 表示尚无完整数据，不能当作该年没有节假日。2026-10-21 获取的真实 2027 年源文件即为空占位，已保存为回归夹具。网络错误、部分年度无效、空占位均保留对应旧缓存；其他有效年度可独立保存。
- 年份按官方文件标题计算，下一年度文件可能包含上一年十二月的修订。先建立完整年度覆盖，再将这些十二月修订应用到已有年度，零散跨年日期不会把未知全年标成可用。
- `verifin.workday_calendar.v1` 一次保存开关、完整年度文件、上次检查时间及未公布/失败年份；原始字段在冷启动重新校验。独立 `ValueNotifier` 只更新工具页和提醒排程；落盘成功后才更新内存，只有有效日期快照变化才重排。网络等待不占用账目串行队列，缓存只保留最近三份年度文件。
- **关闭开关保留离线缓存**，阻止后续年度及备用地址请求，在途已发请求即使返回也不再提交。初始化关闭并清缓存，防止迟到结果恢复授权；删除账户/账本、切换账本和恢复备份不删除公共缓存或扩大联网授权。开关与缓存均不进入备份，旧备份无需迁移。
- **没有常驻后台下载**。提前缓存下一年度后，Android 提醒可跨进程回收、重启及离线使用；长期不打开且未缓存新年度时，仍须打开应用并联网检查。页面展示真实本机可用年份、来源、检查时间和未公布/失败状态，前台检查尚在进行时暂缓“日历缺失”提示。

生产模型与客户端在 `reminder/workday_calendar_sync.dart` / `workday_calendar_client.dart`，操作在 `veri_fin_controller_workday_calendar.dart`，工具页在 `workday_calendar_page.dart`。真实样例来源与 MIT 许可见 `test/fixtures/holiday_cn/README.md` 和同目录 `LICENSE`；样例不打包到 APK。

## 交互与账务口径

- 闹钟只展示系统通知，不自动记账。确认按钮显式授权按预设交易保存；取消仅跳过本次，不处理通知不产生交易。点正文打开统一确认框。
- 两个按钮的动作固定，文字可独立配置。按钮会打开应用；启用应用锁时必须先解锁，再消费操作，不能从锁屏旁路写账。
- 仅当天通知可处理。过期至次日、停用、编辑前旧通知或已删除的账户均不落账。原生负责编入实际触发日期，Dart 不从点击时间猜测旧通知日期。
- 每个账户每天最多处理一次；确认、取消及冷启动后均去重。配置保存生成新修订 id，拒绝旧通知按新金额落账；修改配置仍保留当天已处理标记。
- 确认固定写入原账户及其所属账本，不切换当前浏览账本。原币金额等于账户实际金额，本位币按提醒日期的本地历史汇率换算并冻结；缺率保留操作待重试，不猜测汇率。通知跨账本展示时显式保留币种。
- 删除账户、账本、有效分类或变更账户币种后清理失效配置；初始化全部数据会清空账户提醒。隐藏账户仍是有效账户，不隐式关闭其提醒。

## 存储与原生生命周期

`AccountEntryReminder`（含 `repeatMode`、`missingCalendarPolicy`）和当天处理标记存于 KV `verifin.account_entry_reminders.v1`，使用可等待保存，并通过独立 `ValueNotifier` 更新；属于设备提醒偏好，不进入 JSON/ZIP 备份，旧备份无需新增字段或 SQLite 迁移。恢复备份保留本机仍有有效实体引用的配置，清理失效引用；换机需要重新设置。初始化及删除实体时沿用既有清理路径。

`AppAccountReminderBridge` 复用 `verifin/app` 单一入站分发器。根组件同步全部账本的有效配置，原生 `AccountEntryReminderReceiver` 保存私有配置、按星期或工作日日历安排下一次闹钟，每次触发继续排下一次；开机、升级、系统时间/时区和精确闹钟授权变化后重排，不依赖 Flutter 进程常驻。无精确闹钟权限时回退 `setAndAllowWhileIdle`。系统强行停止应用仍遵循 Android 既有限制，重新打开应用后对齐排程。

时间来自系统时钟和时区，排程沿用 `AlarmManager.RTC_WAKEUP`，不调用手机时钟应用。读取时间没有授权弹窗；Android 13+ 须允许发送通知并开启对应渠道。精确闹钟沿用 GitHub/Play 既有权限差异，无权限则降级；开机接收权限已声明，无新增授权。声音遵循渠道、静音和勿扰设置。

确认/取消点击先存原生队列，Dart 业务成功或判定过期后才确认消费；同一提醒日期以用户最后一次尚未处理的选择为准，缺率后的取消可以覆盖待重试确认。私有随机令牌与不可变 `PendingIntent` 防止外部应用伪造导出 Activity 的记账操作。原生日志只记录阶段和异常类型，不输出配置、账户名或金额。

交易保存复用 Controller 的交易草稿串行队列和 SQLite 原子聚合入口。交易 id 固定为账户＋日期；即使 SQLite 保存后进程退出或辅助 KV 写入失败，重试也不会新增第二笔。取消必须等 KV 标记保存成功；不会以“取消交易”伪造一条零额账目。

## 一分钟测试按钮

入口：**资产 → 饭堂等对应账户 → 账户记账提醒 →「1 分钟后测试提醒」**。无需先保存草稿、填写金额或启用正式提醒。测试标题优先使用草稿提醒名，留空则使用账户名，并标记「测试提醒」。

按钮先申请通知权限，再由 `AppAccountReminderBridge.scheduleTest` 调用原生 `scheduleAccountEntryReminderTest`。测试与正式提醒共用 `scheduleAlarm`、Receiver 和 `verifin_account_entry_reminder` 通知渠道，使用系统 `PendingIntent` 安排约一分钟后的一次性通知，没有 Dart 定时器或常驻服务。原生确认应用通知及该渠道可用后才返回排程结果；无精确权限时返回非精确结果，页面提示可能延迟，不承诺一分钟准时送达。

测试使用独立且固定的闹钟与通知身份，重复测试只替换上一条，不改正式提醒时刻、配置或当天处理标记，也不进入原生记账操作队列。测试正文明确「不会记账」，点通知仅打开应用，不提供真实确认/取消记账动作。测试文案由系统保存，可跨普通进程回收；手机重启不恢复这条临时测试，正式周期提醒仍按现有配置恢复。

## 手动验证应用没有运行时的提醒

先由用户手动编译并安装新版到隔离的 diagnostic 应用；此任务不自动编译、运行测试或操作手机。首次测试允许通知权限，并检查系统「账户记账提醒」通知类别已打开。使用与发布一致的 `UNIFIED_DESIGN_PREVIEW=true`。当前已有公开截图未包含本页，无需替换。

1. **返回桌面/锁屏**：点测试按钮，看到安排成功提示后按 Home 或锁屏，等待约一分钟，在通知栏确认出现带「测试提醒」的通知。非精确排程按系统允许的窗口观察，不能以一分钟未响直接判失败。
2. **划掉最近任务**：重新安排测试，从最近任务划掉应用并等待。有些厂商会附加自启动/后台限制，此步骤不能单独证明进程已退出；未收到时检查系统通知、精确闹钟及厂商后台设置。
3. **明确验证进程已退出**：重新点测试后按 Home，连接已授权 USB 调试的手机，在到点前手动执行下面命令。替换 `<设备序列号>`；默认目标为独立 diagnostic 应用，正式 GitHub/Play 应用包名为 `top.talyra42.verifin`。只结束目标后台进程，不清数据。

   ```powershell
   adb -s <设备序列号> shell am kill top.talyra42.verifin.graphicsdiagnostic
   adb -s <设备序列号> shell pidof top.talyra42.verifin.graphicsdiagnostic
   ```

   `pidof` 无输出才表示此刻没有应用进程；若仍有 PID，本次尚未构成进程退出测试。保持不重新打开应用，等待通知。到点后 Android 为 Receiver 新建进程属于正常行为，说明提醒由系统唤起，无需 Flutter 常驻。
4. **不要用「强行停止」代替上述步骤**：系统设置的「强行停止」以及 `am force-stop` 会让包进入停止状态，Android 会阻止应用继续按普通方式唤起；Android 15 还会撤销全部 PendingIntent。需要用户重新打开应用后恢复正式排程，再重新点测试按钮。这种情况不能承诺继续提醒。
5. **验证真实饭堂确认动作**：测试通知只验证送达。另在隔离应用配置饭堂账户的金额、分类、当天重复星期，将正式提醒设为未来 2–3 分钟并保存；退出进程后等待正式通知。取消/不处理不记账，确认（启用应用锁时先解锁）仅记一笔，重复点击不再新增。切换账本后仍应记回原账户，不能拿测试通知验证这一步。

锁屏一分钟通常不足以进入深度 Doze。更深的休眠验收按 Android 官方 [Doze 测试步骤](https://developer.android.com/training/monitoring-device-state/doze-standby#testing_doze)单独进行并恢复测试设备状态；休眠下短时间反复测试可能受系统闹钟限频影响。

依据：[系统闹钟可跨应用进程生命周期运行](https://developer.android.com/develop/background-work/services/alarms)、[`am kill` 仅终止可安全结束的进程](https://developer.android.com/tools/adb#am)、[Android 15 的停止状态及 PendingIntent 规则](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state)。
