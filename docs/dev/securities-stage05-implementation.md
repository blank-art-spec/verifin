# 证券阶段 5：资产分解、历史依据与恢复

日期：2026-10-24。分支 `codex/securities-trading-quotes-20261023`。依赖已提交的期权阶段 `16528aa`，参考行情机制与来源边界见 [阶段 4](securities-stage04-implementation.md)。

## 当前实现

`investment_valuation.dart` 是资产分解与历史估值的纯计算入口：

- 资产 = 正现金 + 股票/期权多头价值。
- 负债 = 负现金绝对值 + 股票/期权空头义务。
- 净值 = 资产 − 负债。冻结保证金仍在现金内，只披露冻结额和参考可用现金，不再次扣净值。
- 期权张数、明确的权利金乘数和单位参考价共用 `securityPositionValue`。未知成本不妨碍已知市值，但盈亏不完整；缺价格不能当零。

`ConvertedAccountBalances` 新增原币分解经折算后的资产、负债映射及缺历史依据账户集合。逐账户折算，再按目标币种精度分别舍入资产/负债后取净额；零净值但有资产/负债的外币账户仍需要汇率。普通账户继续按现金/信用余额正负拆分。

首页指标及设置预览、资产页、父子账户当前合计、桌面小组件投影、只读 AI 的 `accountsOverview` / `netWorth` 使用一致净值口径。账户余额、资金转出/信用账单仍读真实现金或欠款。AI 接收不可变资产分解及现金快照，不触达 Controller，不增加写账能力；单位隐藏偏好继续生效。收益和买卖不进入日常收支统计。

当前余额保留应用原有“全部已录入事实”的语义；历史接口才按截止时点截断。普通现金批量重放，Controller 当前现金复用原缓存；不为普通账户逐个重新扫描全部交易。投资重放仍遵循聚合行性能阈值。

## 历史依据

投资详情右上角“历史估值”可主动“保存当前估值依据”。只能保存实际当前时点，不能选择过去日期或静默批量补齐。保存内容是每证券价格、手填/来源及原报价时间、保存时本位币和有效参考汇率，不复制原始网络响应，不保存第二份可编辑净值。实际时点以 UTC 保存，界面按设备时区显示。

`InvestmentValuationSnapshot` 随所属 `InvestmentPortfolio` 在 SQLite v28 聚合载荷中原子保存，无表结构变更。快照修订摘要只含截至观察时点影响现金、数量、成本和规格的事实，不含当前参考价、临时缓存或快照自身。今日改价、改汇率及未来成交不重写旧依据；补录、删除或更改观察点之前的事实会使该点失效，保留原价格供复核，不假装已经重建完成。

历史查询只采用查询日当时已保存的最后一份有效依据，按截止时点重放现金和持仓；该日之后的日期不沿用。观察点之后、同一日内的成交仍重放，若新增证券没有当日价格则结果不完整。当前手填价、当前网络缓存及后来新增的汇率不能补齐历史。未启用前、无当日快照、缺价、缺率、账务修订或本位币改变时，不输出部分合计。

历史页展示真实观察点及原币/本位币结果；一个有效观察点只显示说明，至少两个才画趋势，同日坐标显示简短时分、跨日显示月日，完整时间保留在点按详情中；缺汇率仍保留原币依据。资产年度图或小组件历史序列缺依据时隐藏不完整曲线/保留空点，并提示；不生成零值或平滑回填。历史页连接的只是已保存观察点，不代表逐日行情。

当前录入与恢复延续股票阶段的约束：每项持仓必须保留明确手填后备价。删除后备价格的备份会被校验拒绝并保留原数据，不能把它当成已支持的“完全无价格持仓”；B08 的该提案场景尚未开放。历史依据允许缺价/缺率并明确留空。

## 持久化与备份

完整备份升 JSON v12，包含快照、价格/汇率事实与每证券行情覆盖选择。v1–v11 缺快照时默认空，不猜测历史。SQLite schema 仍为 v28；`toJson` / `fromJson` / SQLite 聚合行四向映射覆盖新增载荷。示例备份更新为 v12，无投资数据的样例仍保持空列表。

保存当前依据走原投资命令队列和 `saveInvestmentPortfolios` 原子事务，成功后才发布内存；失败不出现半份历史。删除账户/账本与初始化沿用原聚合清理边界。导入预览先解析和验证，零落库；真实恢复包含历史依据并清设备临时报价，保留本机联网偏好，新设备仍默认关闭。既有整库恢复最终由 `replaceAllLedgerData` 原子写入，原 Controller 恢复流程仍有乐观内存发布的历史边界，不能把单条投资命令的回滚语义夸大为整个旧恢复流程已重写。
