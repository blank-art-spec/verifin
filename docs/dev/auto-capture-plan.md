# 第三批：自动记账与智能识别

> 状态：第一阶段实现于 2026-09-27，仍需 GitHub release APK 真机验收。2026-07-07 的“永久不做监听类自动记账”决定已被本批用户明确推翻；历史失败经验继续作为权限、可靠性和保守落账边界，而不再作为功能禁令。

## 目标与边界

第五批增量：自动采集页支持手动回放当前账本最近 100 条未落账事件。回放跳过已确认、已自动入账、已合并、已忽略及误识别事件，只刷新待复核候选；即使自动入账开关已启用，本次回放也不会新增交易。原始事件仍仅保存在设备本地。
状态卡另显示今日实际入队的事件数与最近捕获时间；它只统计已落库事件，不能证明系统未投递的通知为零，因此不把“漏单风险 0”当成健康结论。

自动采集的目标是“尽快得到候选，少量集中确认，正式账单最终核准”，不是让通知文本直接控制账本。系统能力全部默认关闭，由用户逐项授权：

- GitHub/diagnostic 渠道可启用 `NotificationListenerService` 和“仅接收以后新短信”的 `RECEIVE_SMS`；不申请 `READ_SMS`，不扫描历史短信。
- Play 渠道保留通知监听，但通过 Manifest overlay 移除短信权限和短信接收器，避免把受限短信能力带入商店包。
- 永不使用无障碍读屏、常驻录屏、Root/Xposed/Shizuku。
- 原始通知和短信只保存在应用私有 SQLite；不进入账本备份。正式交易只携带稳定指纹、来源与商户摘要，不复制完整原文。
- 本地规则和历史学习优先；AI 补充识别另设默认关闭的明确授权。开启后，仅当本地结果不足且属于普通收支时，才把该条原文发送到用户自配端点；AI 参与的结果最高为中置信度并始终待确认，不会自动入账。已有 AI 文字/截图识账仍是用户主动触发的独立草稿流程。

## 数据流

```text
NotificationListenerService / SMS BroadcastReceiver
        │ 金融关键词预过滤、原生持久队列（最多 200 条）
        ▼
RawCaptureInput
        │ 长度限制、稳定指纹、sourceEventId 幂等
        ▼
CaptureEvent（SQLite 原始事件 + 可重跑解析快照）
        │ 本地金额/币种/类型/商户/卡尾号解析
        │ 用户规则优先，历史分类/标签建议补充
        │ 可选 AI 补充（默认关闭，结果强制待确认）
        ▼
跨来源去重 ── 高分唯一命中 ──► 给已有 LedgerEntry 追加 sourceRecords
        │
        ├─ 高置信度且关键字段完整 ──► 原子创建 LedgerEntry + 更新事件状态
        ├─ 中置信度/疑似重复 ──────► 待确认队列
        └─ 低置信度 ──────────────► 只保留原始事件
```

原始事件与正式交易通过 `saveCaptureProcessing` 在同一 SQLite 事务提交，避免“账已创建、事件仍待处理”造成重入重复。Schema v19 新增两张表，v20 为事件补充 `ai_assisted` 可解释标记：

原文先于解析快照落库。若进程在两步之间退出，冷启动和回前台会补解析尚未处理的本地原文，补跑只更新候选，不自动入账；点“复核记账”时也会先刷新缺少金额或类型的当前事件。手动“重新解析”只处理所选未落账事件，不触发 AI、自动合并或自动入账，已确认、已忽略等事件不能重试。

复核页保存通过 `saveEntryAggregateDraftResult(captureEventId: ...)` 将交易、来源证据、附件、可选汇率和事件已确认状态放入同一事务，成功后才退出页面。Controller 串行化采集写命令与交易草稿的快照读取、落库及内存提交；AI 等待不占用此队列，提交解析结果时再次核对原事件是否已改变，并以最新交易做去重。只刷新候选时不写交易表。冷启动发现未落账状态的事件已有唯一同账本来源指纹对应交易时恢复已确认关联；忽略、误识别和正常自动入账状态不受影响。

- `capture_events`：来源类型/App 或短信号码、来源事件号、原文、收到时间、解析金额/币种/商户/卡尾号、账户/分类/标签候选、类型、置信度、处理状态、关联交易、命中规则与是否经 AI 补充。
- `auto_capture_rules`：账本内确定性条件和动作，按优先级执行。

## 解析与账务安全

类型判断优先级为退款、信用卡/信用支付还款、转账、返现、收入、消费。还款词先于“到账/入账”等宽泛收入词，避免把信用卡还款污染收入统计。

账户匹配依次使用卡尾号 + 信用主体机构、明确账户名、支付来源名称；出现多个候选或只有“支付宝付款”而不知道底层资金账户时保持空值，不回退列表第一项。多币种按明确币种或唯一账户币种确定，缺汇率时拒绝自动落账。

去重以同账本、币种金额、时间窗口为硬基础，再综合账户、商户和已有来源指纹。高分且唯一才自动合并；分数不足或并列候选进入“疑似重复”。正式账单导入继续复用 `sourceRecords` 与现有核准状态，把通知先记的交易匹配为同一笔真实交易并最终核准。

置信度分三档：

- 高：金额、类型、账户等关键字段完整，且分类/规则/历史证据足够；仅在“高置信度自动入账”开关开启时自动写账。
- 中：进入待确认，可在标准记账页改账户、分类、标签和备注，也可合并到已有交易。
- 低：只保存原始事件，不出现在待确认数字中；可手动重试或标记误识别。

退款必须唯一关联到近 90 天同账户、同币种、同金额的原支出，否则不自动创建。转账、信用卡还款和信用支付还款缺任一端账户时不得自动创建。

## 规则引擎

规则条件之间为 AND，可按来源类型、来源标识、文本包含、卡尾号、精确金额和已识别类型匹配；动作可设置类型、转出/转入账户、分类、标签和商户。规则优先于历史学习，结果会把规则 id 记到事件中以便解释。

规则保存时校验所有账户、分类和标签引用都属于当前有效数据，转出/转入账户不能相同。实体删除后必须清理事件候选和规则动作，避免悬空引用。

## 用户可见控制与纠错

“我的”和“设置”均可进入“自动记账与智能识别”页，页面展示今日识别、自动入账、待确认、疑似重复和未识别数量。用户可以：

- 直接查看通知使用权、NLS 实时连接、原生采集开关、全来源开关、原生待消费队列，以及最近通知在“正文提取 → 金融过滤 → 入队”各阶段的结果；诊断只保存来源与阶段代码，不额外保存通知正文；
- 开关通知监听、短信补充、覆盖银行等全部通知来源、AI 补充识别和高置信度自动入账；
- 打开系统通知访问设置、申请/撤回短信权限；
- 新增、编辑、停用和删除本地规则；
- 审核草稿、合并到已有交易、撤销自动入账、忽略、标记误识别或按新规则重跑。

撤销自动入账会删除对应正式交易并把事件退回待确认；删除正式交易也会清掉事件中的悬空关联。标记误识别保留原文和状态，供用户后续据此修正规则。

## 原生与生命周期验收

复核保存专项使用独立 diagnostic 应用和 `capture_review_integration_test.db`，不读写正式应用数据。第一阶段必须带 `--no-uninstall`，否则 Flutter 测试工具会自动卸载诊断包并删除测试数据库。在真实页面点击复核与保存后，强停诊断应用再运行第二阶段，从新进程读取已确认状态，检查同一输入和候选回放均不会重复记账；第二阶段结束删除专项测试数据库并由测试工具清理本任务诊断包。运行前确认诊断包中没有需要保留的用户数据。

```bash
flutter test integration_test/capture_review_test.dart -d <device-id> --flavor diagnostic --dart-define=UNIFIED_DESIGN_PREVIEW=true --no-uninstall
adb -s <device-id> shell am force-stop top.talyra42.verifin.graphicsdiagnostic
flutter test integration_test/capture_review_test.dart -d <device-id> --flavor diagnostic --dart-define=UNIFIED_DESIGN_PREVIEW=true --dart-define=CAPTURE_REVIEW_PHASE=reopen
```

正式完成必须用 CI release APK 真机覆盖：

1. 首次授权、拒绝、撤权后页面状态与实际系统权限一致；未授权时不采集。
2. App 冷启动、后台、划掉最近任务和进程重建后，原生队列不丢事件；回前台能排空并幂等入库。
3. 支付宝、微信、云闪付、美团、京东和至少两家银行通知；同笔支付平台 + 银行通知只形成一笔交易。
4. GitHub 包只接收授权后的新短信，不读取历史短信；Play 包无短信权限/接收器。
5. 同一通知槽位连续更新或复用时，新交易不会被旧 key 吞掉；重复回调仍保持幂等。
6. 通知内容变化、缺金额、卡尾号歧义、多币种缺率、退款/还款/转账均保守进入待确认或只存原文。
7. AI 补充开关关闭时不发出原文；开启后普通收支可得到待确认候选，端点失败保留本地结果，金额/类型冲突时拒绝 AI 结果。
8. 月底导入正式银行账单后匹配既有自动交易，来源证据追加且核准状态更新，不复制交易。

监听服务实现 `onListenerConnected` / `onListenerDisconnected`：断开时在 Android 7.0+
主动请求 `requestRebind`；重连后补抓“本次开启采集之后、上次断开之后、最近 24 小时”
三者交集内仍驻留通知栏的活动通知，稳定事件号继续负责幂等。正文提取覆盖标准标题/正文、
BigText、多行文本、副标题、摘要、信息文字、MessagingStyle 当前/历史消息与 ticker；完全由
自定义 RemoteViews 绘制且不提供这些字段的通知会在诊断中明确显示 `textUnavailable`。

原生开关和原始队列都在返回成功前同步提交 SharedPreferences，保证应用随即退后台或进程
被系统回收时不会只停留在异步写队列；每次启动、回前台和打开自动识别页都会用 Dart 权威
设置重新对齐原生配置。系统授权存在但 NLS 未连接时，原生同步会请求重绑，页面也提供手动
“尝试重连”入口。
