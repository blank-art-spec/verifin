## 1. 已确认目标和范围

用户希望在 Veri Fin 的证券账户记录美股、A 股、港股及其场内期权，并以最新可用报价更新参考市值；可以接受行情延迟。希望手机直接联网，不部署自有后台，不要求用户安装 Python、注册额外行情账号或申请个人 API Key。

采用两条独立完成线：

| 完成线 | 必须具备的能力 | 完成条件 |
| --- | --- | --- |
| 交易与持仓 | 三地股票/ETF，三地股票、ETF、股指期权的手工建档和记账，期初持仓，多空、开平仓、结算，费用及多币种 | 不联网也能完整保存、重算和恢复，数值验收通过 |
| 公共参考行情 | 经验证且使用条件适合的公开报价接口，手机直连、延迟标识、缓存、手填参考价 | 每一个宣称支持的市场/品种均有 Android 实测证据及明确数据时间；未通过的项显示未支持 |

不能用“支持手工录入”替代“已支持自动行情”。若港股期权或其他品种没有满足免账号、免后台条件的可用来源，仍须提供手工估值，但该项自动行情保留未完成状态，不静默增加券商授权或服务器依赖。

本轮完整功能不包含：真实下单、撤单、自动交易、投资建议、税务申报、自动测算券商保证金/购买力、完整期权链扫描、Greeks 策略分析、商品期货和加密货币。未来第三方券商账单导入必须有真实样例，再经既有导入预览确认；本方案不臆造格式。

## 3. 用户操作与页面

### 3.1 启用与期初确认

1. 从“资产 → 证券账户”进入。未启用时保持原有余额显示，并提供“启用证券持仓”入口；不在升级时自动拆分旧数据。
2. 选择生效时间，确认现有余额表示“现金”还是“现金与持仓合计”。
3. 填写每个币种的真实期初现金，以及已有持仓的数量、成本总额或成本未知状态。已有空头须单独确认方向和未平仓成本/权利金。
4. 预览启用前后现金、持仓、缺价项和账户合计。点保存后一次提交；取消无任何变更。
5. 联网行情另设默认关闭的开关。启用持仓不自动同意联网；先手填价格即可完成记账。

旧账户原值若为总资产 10,000，其中现金 5,000、股票 5,000，启用后应为现金 5,000 + 股票 5,000 = 10,000，不能变成 15,000。不得改写历史买卖或凭空生成一笔 5,000 日常支出。

### 3.2 证券账户详情

顶部按账户展示币种显示“账户净值、现金、持仓净值、未实现盈亏、已实现盈亏”，多空责任和负现金单列。持仓区显示代码、市场、方向、数量、成本、参考价格、参考市值、盈亏、报价来源与时间。缺成本时盈亏为“未知”，不能用零成本制造盈利。

提供“持仓 / 投资记录 / 资金流水”分区及“买入、卖出、期权交易、股息/利息、期初/公司行动”入口。资金流水同时展示既有普通流水和证券事件的真实现金腿；显示同一事件详情，不生成第二笔可独立编辑的交易。

证券买卖详情填写市场、证券/合约、币种、成交时间、数量、真实成交价、手续费、税费、备注；行情只能给出参考值，不能静默替换真实成交价。搜索不联网时支持手工建档，标记资料待核实。

期权额外填写认购/认沽、到期日、行权价、买/卖方向、开/平仓、权利金报价单位、权利金乘数、交割内容、交割方式和币种。不能仅以股票代码或一个模糊合约名称保存。

### 3.3 复用与外观

使用 Scaffold > SafeArea > VeriPage、VeriHeader、VeriCard、SummaryMetric、既有账户选择器及日期金额输入；弹层由具名 context: 的 show…Sheet helper 封装。确认/破坏性操作复用 showConfirmDialog，反馈复用 VeriFeedbackHost。

全部表面使用不透明实色，沿用设计令牌；不加玻璃、模糊、折射或光效。沿用统一设计参数，保留旧外观路径。所有新增用户文案同时进入中英文 ARB，生成文件由工具生成，不手改。

证券价格、持仓数量、成本每股等不按普通现金两位小数截断，拟扩展共享格式化 helper 并登记 components.md；现金仍按币种 minor unit 格式化。中文注释解释各新增/改动方法的功能、参数、返回值、失败和边界；新增日志采用中文隐私友好内容。

## 4. 账务规则与公式

### 4.1 现金与日常收支

- 银行与证券账户间入金/出金继续使用已有转账，一笔两端真实金额，不计日常收支。
- 股票买入、卖出、卖空、回补、期权开平仓等保存为独立投资事件及其资金腿；只由这些资金腿影响现金，不能又生成普通 LedgerEntry 重扣/重加。
- 股息、利息、交易费用、税费、融资利息均在投资报告单独统计；本方案不将同一现金事件再写入普通收入/支出。普通消费预算、分类报表保持原规则。
- 手续费/税费作为净成本或净卖出所得的一部分；报告中的费用累计是说明项，不能再减一次。
- 现金按成交确认时间计账，另存实际清算日期/状态；清算状态更新不能重复收付款。“账面现金”不宣称等于券商可取资金或购买力。
- 负现金只能在明确允许并确认真实融资/透支后保存，作为负债展示。不能默认禁止所有真实融资，也不能静默生成借款。

### 4.2 持仓、成本与盈亏

每个账本、真实币种账户、证券、方向分别重放事件；顺序为业务时间加稳定序号。股票/ETF 默认移动加权成本，期权按具体合约和多空方向独立计算。不是税务成本方法；本轮不混用 FIFO 或用户选择批次。股票碎股允许小数数量，期权交易张数必须为正整数，拆分/调整后的交割数量不受此整数约束。

| 动作 | 现金变化 | 持仓和成本 |
| --- | --- | --- |
| 买入股票/多头期权开仓 | 减成交金额及费用 | 增数量，增加含费用成本 |
| 卖出股票/多头期权平仓 | 加成交金额减费用 | 减数量，释放按比例分摊的成本；净所得减释放成本为已实现盈亏 |
| 卖空股票/空头期权开仓 | 加成交金额减费用 | 增空头数量及净开仓所得，同时记录按当前价格估算的回补义务 |
| 回补股票/空头期权平仓 | 减成交金额及费用 | 减空头数量；分摊净开仓所得减回补总额为已实现盈亏 |
| 股息/利息/融资费 | 按真实净额增减 | 不直接改持仓数量；税费拆项仍只扣一次 |
| 拆股/合股 | 通常无现金，零碎股兑现另记 | 按真实比例变数量，保留总成本；不把复权历史价当真实成交价 |
| 持仓转移 | 同币种内部划转不产生现金或盈利 | 两端原子增减数量、继承分摊成本，不能凭转入价制造收益 |

多头未实现盈亏 = 当前参考市值 − 剩余含费成本。
空头未实现盈亏 = 剩余净开仓所得 − 当前回补义务参考值。
同一合约的多头和空头不得默认互相抵销，平仓不能超过指定方向数量；一次穿越零仓位须显式拆成平仓和新开仓。

同币种账户净值 = 账面现金 + 多头参考市值 − 空头回补义务参考值。
冻结保证金仍包含在现金中，只降低可用参考现金，不再从净值扣一次。这里只记录用户/来源确认的冻结额，不推算券商风险保证金。
投资净盈亏 = 已实现净盈亏 + 未实现盈亏 + 净股息/利息 − 未纳入成本的融资等费用。
跨币种盈亏不直接把不同币种相加；先原币核对，再折算展示，汇率影响另作标识。

### 4.3 数值精度

新证券数量、价格、行权价和乘数采用十进制文本存储，内部解析为整数与小数位数，用精确十进制运算，不经 double 往返。初版最多支持 8 位数量/价格小数，超过上限明确校验，不截断；乘数和交割数量精度单独验证。

成本总额、费用和现金按结算币种 minor unit 保存精确整数文本，按项目已有规则在边界归一；分批平仓按比例分摊并把舍入余数留给剩余仓位，最后一笔释放全部余数，避免平仓后残留几分钱。计算金额与券商真实净额不同时允许明确的结算舍入差额项，展示原因，不偷偷改数量或价格。

既有普通现金的 double / SQLite REAL 暂不全库迁移；证券精确结果进入现金聚合边界前检查数值范围并按币种归一，禁止 NaN、Infinity、溢出或转型丢失精度。必须覆盖碎股、0.0001 报价、负现金和多笔部分平仓。

## 5. 期权生命周期

权利金总额 = 每单位权利金 × 权利金乘数 × 张数。权利金乘数、实际交割股数/现金篮子是不同概念，不因拆股或调整合约就把两者强制设为相同；禁止美股、港股、内地期权统一写死为 100。合约规格参考交易所/结算方资料，无法确认时须用户补齐并标记。

| 场景 | 保存与估值约定 |
| --- | --- |
| 买入开仓/卖出平仓 | 使用多头规则；两次权利金现金变动和费用均可追溯 |
| 卖出开仓/买入平仓 | 使用空头规则；收到权利金时同时有回补义务，不能当纯盈利 |
| 确认无价值到期 | 用户确认后按事件关闭仓位并结转剩余成本/净开仓所得；没有报价、过了到期日都不能自动判零 |
| 现金交割 | 确认真实交割金额和费用，一次关闭合约、保存现金腿及已实现盈亏 |
| 实物行权/被指派 | 同一事务保存期权关闭、股票增减、行权现金及费用；不足股票/现金须明确处理，不生成悬空半笔 |
| 提前行权、调整合约 | 使用真实发生日期和交割内容；资料不足进入待补全，不根据最新股价猜测 |

实物交割的投资绩效成本统一约定：多头认购的剩余权利金成本并入购股成本；空头认沽的剩余净权利金抵减购股成本；多头认沽的剩余权利金减少卖股净所得；空头认购的剩余净权利金增加卖股净所得。期权关闭时不再重复确认同一份权利金盈亏。交割费按其对应股票购入/出售腿归集。

同币种标准合约优先实现；涉及非标准交割篮子或不同结算币种，必须明确每一现金/证券腿及成本分配，并可预览原子保存；不支持的结构明确拒绝确认，保留待处理状态，不能丢弃或归零。无股票覆盖的认购指派只有用户确认后才产生股票空头义务，并按股票空头规则持续估值。

## 6. 期初、编辑、删除与现金锚点

拟建 InvestmentOpening 保存启用时点、真实现金和期初持仓/成本；这是显式的核对基准，不是一笔消费，也不伪造历史成交。

- 已启用账户的现金读取，在 InvestmentOpening 与已有有效 BalanceAnchor 中选择最新现金核对基准，仅叠加基准之后的普通及证券现金变化；持仓始终按其期初和证券事件独立重放，现金锚点不能抹除持仓。
- 基准保存生效时刻及该时刻已包含的普通流水/证券事件 ID 集合，解决同秒重复包含/漏算：更早的现金腿不再累加，等时且已包含的记录不重复计入，等时但后来新增的记录正常计入。证券事件另持久化稳定顺序用于重放；导入和恢复保留 ID 与顺序，不只使用严格大于时间来隐式丢记录。
- 期初之前不接受新证券事件，除非显式更改基准并重新预览。回补/编辑基准前普通流水时明确说明基准后现金仍受已核对余额约束，需要重核基准，不静默重算出另一笔现金。
- 编辑、删除及补录历史证券事件时，重放该账户受影响时间之后的数量、成本和现金；若导致后续超量平仓或无法交割，保存失败并列出冲突，不静默修正后续交易。
- 每个保存请求有稳定幂等键；重复点保存、失败重试、相同外部成交 ID 不重复建事件。未来导入与手工证据合并须显式核准，不能仅凭同日同额误合并。
- 暂停联网仅停请求；暂停证券新记账保留已有持仓估值。已有证券数据不能一键切回“普通余额模式”导致资产消失；退出需先完成转出/平仓或通过完整数据恢复。
- 删除账户/账本须明确列出受影响持仓、事件、现金腿、保证金和估值记录；经确认后原子清引用。不删除其他账本或共享静态资料；隐藏/不计入资产遵循既有规则，不能丢数据。

**博通 P0 的具体产出：** 同一台 Android 测试设备上分别验证 AVGO 普通股、一个真实认购、一个真实认沽；记录请求路径、来源固定版本、合约规格依据、未复权价格/报价单位、源时间与抓取时间、网络可达性和失败状态。先验证单合约或受控分页，不下载完整期权链反复轮询；来源若只能返回超过资源预算的数据，应标记暂不可用。若使用匿名会话 Cookie，只允许按来源正常流程临时获取，不复用用户券商登录，不绕过验证。

2026-10-23 的网页调研只确认了博通官方 AVGO 身份，以及公开网站存在相应期权页面：Nasdaq 页面本次提取显示期权链暂不可用；Cboe 搜索快照显示旧日期，不能选为当前合约或最新报价依据。Yahoo/yfinance 是待验证候选，仓库明确提示个人用途限制；因此“博通股价 + 两个真实期权均可在手机免账号取得”的门禁仍未通过，不能承诺仅移植 AKShare 就已满足美股期权需求。网页人工对照入口不自动成为生产数据适配器。

### 7.2 行情协议与字段

拟建 MarketQuoteClient 接口和按来源拆分的适配器，测试通过可注入传输返回脱敏真实 fixture。能力需精确到市场、品种、批量范围、价格类型和可用时段，不只返回一个 supportsMarket=true。

QuoteObservation 保存证券身份、来源、原始标识映射、币种、报价单位、最新成交价、买价、卖价、各字段时间（可空）、抓取时间、交易状态及来源标称延迟。没有供应方时间时显示“抓取时间、报价时间未知”，不能把抓取时间伪装为成交时间。

股票默认采用最近成交参考价；期权默认采用有效双边买卖价中间值，若无有效双边价格，使用带明确时间的最近成交参考价并标识。只有单边报价或买卖倒挂时不计算中间价；用户可以手填估值或明确切换参考价口径。买卖价、成交价各自可能陈旧，不能只验证整个响应时间。

参考价只用于估值，不代表可成交价格。手工参考价需用户选择“持续使用至恢复自动”或“仅补本次”；持续覆盖优先，解除后才重新采用网络价。缺失值、空响应不当作零，合法的零估值须明确确认来源/状态或手工输入；零值不自动关闭期权。

### 7.3 请求、缓存和生命周期

- 联网默认关闭；开关独立于持仓功能，开启时说明查询证券/合约代码及服务方可见 IP，不发送数量、成本、账户名称、余额、备注或交易明细。
- 手动刷新取消应用本地五分钟等待，请求未结束时防止重复发送。联网与自动刷新默认均关闭；开启后，在打开软件、回前台或解锁且隐私/首次引导已通过时，检查当前账本全部证券账户的已支持持仓，不依赖行情页可见。尝试时间、自动计时及刷新状态按账本/币种账户独立，冷却未结束时等待原定到期时间，前台持续默认 5 分钟一次，最终服从来源更严格的自动间隔；手动刷新不推迟自动计时。联网与自动开关仍为设备偏好。同来源请求合并，不抓取全市场再筛持仓，不绕过实际限流或 HTTP 拒绝。
- 网络上限：每来源并发不超过 2、单次总超时 15 秒、响应流累计上限 512 KiB，超限立即停止。来源不支持受控单标的/分页请求时先验证资源预算，不盲目放大全市场响应。
- 只访问适配器内固定 HTTPS 主机；重定向校验目标，不执行上游脚本、不下载远程代码、不绕过登录/验证码/访问限制。限流、403、结构变化须降级并记录，不高频重试。
- 离开参考行情页不暂停有效前台会话；退后台、锁屏、退出或进程回收停止后续调度，不申请常驻服务、通知、无障碍或短信权限。回前台重新检查本机开关、隐私/引导及解锁状态、当前账本和账户计时，不在后台持续刷新。
- 请求携带账本/账户及授权修订号；关闭开关、删除持仓、切换账本、初始化或恢复后使在途结果失效。提交缓存前重读当前状态，不能覆盖新的手填价格/较新报价。
- 校验身份、币种、报价单位、负数/非有限数、明显未来时间、响应体和结构；旧时间报价不得覆盖新时间报价。无时间或时间异常返回不确定状态，不编造延迟数字。
- 休市/停牌使用最近有效价格并显示状态；陈旧判断结合来源延迟、交易时段和可获得的日历信息，不把整个周末都误报断线。无法确认交易状态时明确未知，不猜交易所开市。
- 网络失败保留旧缓存及原报价时间，显示失败/过期；缺价持仓只列数量和成本，整体估值显示不完整，并可查看已知部分，禁止把部分和冒充完整总额。
- 新增行情日志只记录来源、耗时、状态码、数量及脱敏错误；不写完整响应、持仓明细或 Cookie。

## 8. 模型、存储和原子提交

下列名称是初始完整方案提案。当前股票/期权采用 v28 投资聚合，设备行情缓存及历史依据载荷见阶段 4–5；不能把下表尚未采用的多表拆分当作已经建表。

| 模型/表 | 权威内容及约束 |
| --- | --- |
| SecurityInstrument / security_instruments | bookId、市场/交易所、证券稳定身份、币种、品种、代码与别名；同一代码不同市场不得合并；期权包含完整身份、权利金乘数和交割资料版本 |
| InvestmentAccountSettings / investment_account_settings | 真实账户启用关系、期初引用、投资成本方法版本；父主体 ID 不作现金账户 |
| InvestmentOpening / investment_openings | 真实账户生效时点、序号边界、核对现金、期初多空持仓和已知/未知成本；相关明细可拆子表 |
| InvestmentEvent / investment_events | bookId、事件 ID/幂等键、账户/证券、业务时间与顺序、方向/类型、数量/价格/费用、外部证据、关联交割/转移批次及审计修订 |
| InvestmentCashMovement / investment_cash_movements | 事件关联的实际现金腿、币种账户、金额、日期、作用类型；同事件同腿唯一，不能另存为重复 LedgerEntry |
| InvestmentReservation / investment_reservations | 用户确认的冻结保证金/解冻事件及余额；不改变总现金，不进信用账单 |
| ManualValuation / investment_manual_valuations | 手填参考价、有效时间、覆盖方式与修订；属于用户数据 |
| QuoteObservation / market_quote_cache | 已验证的外部价格/元数据、源时间、抓取时间、质量状态；设备缓存，无持仓数量 |
| InvestmentValuationSnapshot / investment_valuation_snapshots | 估值时点、当时价格及汇率依据、完整性、对应事件修订；用于历史，不能被今天的行情重写 |

所有用户数据按 bookId 隔离，事件/资金腿必须与真实账户同账本；显式外键及唯一约束保证无悬空引用。持仓数量、成本和已实现盈亏由事件重放计算，不维护另一份可独立编辑的持仓权威余额。

新增 saveInvestmentAggregate：把证券定义/期初/成交/资金腿/交割/保证金等相关集合在同一事务保存；事务成功后才替换 Controller 内存。写入串行化、失败不阻塞后续写，保证仓储行快照同步。删除/恢复/初始化仍扩展 replaceAllLedgerData 的整替边界。不能先 saveEvents 再 saveCashMovements 而留下半笔交易。

当前股票实现已升 SQLite v28，采用单账户投资聚合表（见阶段 0–2 记录）；下表多张投资表是未来细分提案。后续新增表须再次提高 schemaVersion、更新 _schemaCurrent、追加 _migrations，禁止修改 v28 及更早历史。四向映射 toJson/fromJson/toRow/fromRow 均覆盖精度、可空字段及非法枚举，未知事件类型不能静默退回“买入”。

报价缓存独立轻量保存，不与账务编辑争用长事务；缓存失败不伪装为持久保存成功，明确“本次报价未缓存”。交易保存失败必须可见、完整回滚。

## 9. 资产汇总、多币种和历史

拟建 InvestmentAccountValuation / PortfolioValuationResult，返回现金、多头值、空头义务、净值、冻结额、成本、盈亏及缺价/缺率/未知成本列表。所有普通账户走原逻辑，已启用证券账户统一走此估值入口。

资产页分区合计、证券父账户、首页资产指标、看板资产趋势、小组件和只读 AI 资产查询均使用同一口径，不能只修改证券详情页。非信用投资账户如有负现金/空头，资产与负债展示须满足“总资产 − 总负债 = 净资产”，不能在现金已为负时又重复扣融资负债。

同币种先加减，再使用现有汇率投影折为主体展示币种/账本本币；不覆盖原币金额。报价时间和汇率生效日分别展示。证券数量/币种同时纳入多币种显示判断，不能因现金为零就隐藏持仓单位。

历史走势图只使用该历史时点可用的持仓、现金、价格和汇率。保存当时估值依据；晚到旧报价不能覆盖新记录，今天的参考价不能回填过去每个月。无历史价/无快照的月份显示缺失，不造平滑曲线。补录历史事件后使受影响的派生快照失效，并仅用已有历史依据重建；不能篡改用户确认的成交和手填事实。

## 10. 备份、恢复与安全退路

当前完整备份 JSON v12，包含期权事实、历史价格/汇率依据与覆盖选择；保留 BackupService 的 ZIP/加密信封兼容。以下范围以阶段 3–5 的当前实现记录为准。

| 数据 | 进完整备份 | 恢复/初始化语义 |
| --- | --- | --- |
| 证券身份/期权规格、启用关系、期初、事件、资金腿、保证金、证据、审计 | 是 | 原子恢复；初始化删除全部；不得留半个交割批次 |
| 用户手填参考价、持续覆盖选择 | 是 | 原样恢复，不能被启动网络请求覆盖 |
| 已保存历史估值快照及其价格/汇率依据 | 是 | 明确快照版本与完整性；能核对净值，不冒充逐笔行情档案 |
| 原始网络响应、临时搜索/报价缓存 | 否 | 换机重新获取，离线先显示手填/历史参考及其旧时间，缺价就提示不完整 |
| 联网开关、刷新周期、尝试时间、来源健康状态 | 否 | 新设备默认关闭；恢复不覆盖本机已有授权偏好，但清理待替换账本的缓存并使在途请求失效 |
| 未来可能的个人 Key/Cookie | 否 | 本轮不引入；也不得塞进任何备份或日志 |

v1–v9 旧备份新增集合按空恢复，所有旧证券账户保留“未启用”及原始余额。新版本预览/导入/再导出需保持数量、成本、幂等键和资金腿一致。v10 不承诺旧版应用可识别；展示最低支持版本，不建议降级，不要求清数据。

回退方式：开发包始终隔离；正式用户只做保留数据的覆盖升级。上线故障时可先关闭联网、保留手填估值及账务，不能通过删除持仓/回改数据库版本“修复”。实施前保留完整备份；本方案不自动导入用户真实备份。

## 12. 实施分阶段与交付门禁

下表是完整目标。股票阶段 0–2 的当前代码与真实验证见专项实现记录；阶段 3 的期权已实现，阶段 4 已有刷新/缓存机制及显式诊断股票研究来源，生产来源仍未准入，阶段 5 已实现有依据的资产历史（缺日不回填）。模板及模拟器基础已准备，见 1.2。每阶段以可核对成果和测试提交，不把“文档已列出”标成实现完成。开发顺序先完成 AVGO 股票及期权主流程，再补齐其他市场来源；通用模型及账务规则从开始即保留三地和多币种能力。

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| P0 数据源验证 | 优先 AVGO 普通股、真实认购、真实认沽的手机验证及合约记录；同时维护六类覆盖表、固定源码引用、脱敏响应、使用条件与时间字段 | B01、B06 的来源门禁有明确结论；其他项逐一标记可用/不可用/待验证，不能以网页/模拟数据证明网络接入 |
| P1 模型与持久化 | 精确运算、模型、v28/JSON v10、原子仓储和旧数据迁移 | 迁移、四向映射、两种仓储契约、写失败与旧备份用例通过 |
| P2 离线股票持仓 | 先跑通 USD 入金及 AVGO 买入、估值、部分卖出；补齐卖空回补、股息、拆股和转移 | B02–B03、A01–A06、A10、A12 及对应计算测试通过 |
| P3 期权生命周期 | 先以 AVGO 为标的验证认购/认沽及多空开平；补齐保证金、到期、现金/实物结算和待处理状态 | B04–B05、A07–A09、A11 及非标准交割边界通过，不能无报价自动清仓 |

首个可评审成果应为“AVGO 股票及认购/认沽完整闭环”，包括离线账务、真实报价门禁、组合净值、备份重读和隔离 Android 证据；若真实报价失败，只能交付“AVGO 手工账务验证通过、自动行情待完成”的准确状态，不能将其标为闭环完成。此里程碑不等于三地全品种交付或发布授权。

## 14. 开发前需解决的明确问题

1. 港股期权免账号公共报价尚未确认；不能给出虚假的全部覆盖承诺。
2. 美股期权公开来源的发布使用条件及国内手机网络可达性尚未确认。
3. 具体来源的报价时间、乘数、清算/调整合约元数据及限流需真实样例验证；文档中的“实时”不是实测延迟保证。
4. 非标准期权交割篮子需真实合约案例与完整成本分配 fixture；资料不足应保持待处理。
5. 旧账户原余额是现金还是总资产无法自动推断，必须通过期初确认解决。

这些问题不阻止本地建档/精确计算的开发，但对应自动行情和特殊交割不能在验收记录中勾选通过。
